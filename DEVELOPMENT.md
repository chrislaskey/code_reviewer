A macOS desktop app with three features:

* **Reviews**: what a change did in an Elixir or Rust repository, function by
  function, file by file and group by group. Pick a repository and what to
  compare (uncommitted changes, one commit, or a branch against another), then
  read it on a canvas of groups and files, or as ledgers of functions, calls,
  callers and code.
* **Traces**: a test of the same comparison, with every call below it walked
  top to bottom like a stack trace. Changed functions show their diff,
  unchanged ones their name, calls outside the project a slim row, to read
  what a change does on the path a test takes.
* **Sessions**: the tmux sessions this app started, named `cr-<name>`, with
  the agent (Claude Code or Cursor) status (busy, idle) in each, and a form to start a new one:
  a git worktree of a repository and a tmux session, both named `cr-<name>`,
  running Claude Code, opened in your terminal app. After a restart the
  worktrees are found again in the repositories under `~/code`, and a
  session can be continued in one. Each shows its git status, and is
  finished from its Complete menu: Merge into `main` (fast-forward `main`,
  remove the worktree, delete the branch) or Turn into branch (remove the
  worktree, keep the branch), as `bin/worktree` does. Its Review and Trace menus open
  the worktree's uncommitted changes, or everything its branch committed
  against `main`, in Reviews or Traces.

It is built on the [Starter Pack](https://github.com/chrislaskey/starter_pack) template's Tauri app, with
the analysis from the earlier prototypes in `../existing/`. The decisions
behind the rewrite are in `docs/decisions.md`.

## Layout

```
core/            the analysis library: git comparisons, function changes, call links, groups
tauri/           the desktop app
  src/           the pages, a Svelte app with one HTML entry per page (see tauri/README.md)
  src-tauri/     the Tauri crate: the commands the pages call
docs/            decisions.md, and suggestions/ for what was left out
bin/check        every check: fmt, clippy, tests, svelte-check, build, audit
bin/dev          starts the desktop, ios and/or android apps against one Vite server on $PORT (the sessions set one per worktree); `bin/dev --help`
```

## Running

Prerequisites: Rust (stable), the Tauri CLI
(`cargo install tauri-cli --version '^2' --locked`), Xcode command line
tools, Node and pnpm (see `.tool-versions`), and tmux for the sessions
pages.

```sh
bin/dev                            # the desktop app
bin/dev desktop ios "iPhone 16"    # the desktop app and the iOS app in that simulator
bin/dev ports                      # the port it would use
```

Every target loads its pages from one Vite dev server, on `PORT` when set,
else on 1420, or 2420 when 1420 is taken. Ctrl-C stops them all.
`bin/dev --help` has the rest.

`bin/check` runs the checks `AGENTS.md` asks for before a task is done.

## Adding a feature

1. Add the function and its request and response types to `core/`, or to
   `server/` when it works on the host (tmux, git worktrees, agents).
2. Add a method for it to `Backend` in `server/src/backend.rs`.
3. Add a route for it, `POST /api/<command>`, in `server/src/http_api.rs`,
   with a body type in `server/src/requests.rs` when the command takes
   loose arguments rather than a core request type.
4. Add a method for it to `BackendClient` in `client/src/lib.rs`.
5. Add a Tauri command in `tauri/src-tauri/src/` that calls the client
   method, list it in `build.rs` and allow it in `capabilities/default.json`.
6. Add a function for it to `tauri/src/lib/backend.js`.
7. Use it from a page under `tauri/src/`.

## The iOS app

The same Tauri app builds for iOS, where it starts no server and reaches a
paired computer instead (decision 25). The Xcode project is in
`tauri/src-tauri/gen/apple`, generated by `cargo tauri ios init`.
`bin/dev ios "iPhone 16"` runs it in that simulator, with live reload. To
build it without the dev server and run it:

```sh
cd tauri
cargo tauri ios build --debug --target aarch64-sim
xcrun simctl install booted "src-tauri/gen/apple/build/arm64-sim/Code Reviewer.app"
xcrun simctl launch booted com.chrislaskey.codereviewer
```

A phone needs a signing team in `bundle > iOS > developmentTeam` of
`tauri.conf.json` (or `APPLE_DEVELOPMENT_TEAM`). To pair it, turn on remote
access on the desktop's Remote page (Tailscale running, HTTPS certificates
on for the tailnet), pair a device, and paste the code on the phone's
Remote page.

## The backend server

The desktop app starts the backend server on a free localhost port at
launch, and its Tauri commands reach it over HTTP with the token in
`desktop_token`, in the app's data directory
(`~/Library/Application Support/com.chrislaskey.codereviewer/` on macOS).
